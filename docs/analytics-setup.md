# Подключение аналитики в Cloudflare

Код аналитики и миграция находятся в репозитории. Перед включением панели
нужно один раз привязать D1 и задать Telegram ID администратора.

## Через Wrangler

1. Авторизоваться в Cloudflare: `npx wrangler login`.
2. Создать базу: `npx wrangler d1 create grani-analytics`.
3. Добавить выданные Cloudflare `database_id` и имя базы в `wrangler.jsonc`:

```jsonc
"d1_databases": [
  {
    "binding": "ANALYTICS_DB",
    "database_name": "grani-analytics",
    "database_id": "<ID, выданный Cloudflare>"
  }
]
```

4. Применить схему: `npx wrangler d1 migrations apply grani-analytics --remote`.
5. Задать ID владельца: `npx wrangler secret put ADMIN_ID`.
6. Развернуть Worker из этой версии проекта. Рассылка обрабатывается
   запланированным событием раз в минуту.

Для локального запуска используйте те же шаги с `--local` для применения
миграции. Не добавляйте реальный Telegram ID или токен бота в Git.

Пока binding `ANALYTICS_DB` и секрет `ADMIN_ID` не заданы, обычные сценарии
бота работают как прежде, а `/admin` сообщает, что база ещё не подключена.

## Аудитория сообщений

По решению владельца от 29.09.2026 новая аудитория `all_users` включает всех
пользователей базы с `chat_available=1`, без отдельной подписки. Поля согласия
остаются историческими и не переписываются. Старые очереди `all_consented`
не расширяются. Блокировка исключает доставку при ответе Telegram 403.
«Тест только мне» адресуется лишь администратору. Для каждого нового запуска
нужны предпросмотр и подтверждение. Приветствие не изменяется.

## Личные сообщения и ответы

В карточке пользователя есть «Написать» и «Переписка». Отправка выполняется
после предпросмотра и подтверждения. Ответ через Telegram «Ответить» на личное
сообщение или новую рассылку попадает в CRM и уведомляет администратора.
Ответ вне такой цепочки обрабатывается обычными сценариями бота.
Вложения в ответе копируются администратору, в истории отображается их тип.

Таблицы `crm_messages` и `analytics_delivery_locks` создаются автоматически
при первом использовании; ручной запуск SQL не требуется. Их схема также
сохранена в `migrations/0002_crm_messaging.sql`. Тексты переписки отделены от
метрик аналитики. Первая порция подтверждённой рассылки запускается сразу,
остаток обрабатывает минутное расписание. Общая блокировка исключает
одновременную работу немедленного запуска и расписания.
