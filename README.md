# Брокер ГРАНИ — мини-приложение Telegram

## Структура проекта (модульная, по файлам/папкам)

```
/index.html                                 ← Главный экран (интерфейс, макет). Ничего про утильсбор.
/.nojekyll                                  ← служебный файл для GitHub Pages, не трогать
/.github/workflows/update-spravochnik.yml   ← робот автообновления справочника с Яндекс.Диска
/scripts/convert-spravochnik.js             ← скрипт робота: сжимает xlsx в быстрый формат для браузера
/tabs/
  /utilsbor/
    index.html                ← вкладка «Утильсбор» — полностью самостоятельная страница
    spravochnik.xlsx          ← база авто, как есть (обновляется автоматически, раз в час)
    spravochnik.json.gz.b64   ← та же база, сжатая для быстрой загрузки (тоже автоматически)
    rates.xlsx                ← таблица ставок утильсбора (обновляете вручную, когда меняется закон)
```

**Главный принцип:** каждая вкладка — это отдельная папка в `/tabs/` с полностью независимым `index.html`. Правки в `/tabs/utilsbor/` никогда не затрагивают главный экран, и наоборот. Как добавить новую вкладку в будущем — см. раздел «Как добавить новую вкладку» в конце.

Сейчас рабочая только плитка **«Рассчитать утильсбор»**. Остальные плитки и «Мои заявки» — заглушки, по тапу показывают «Этот раздел скоро появится».

---

## Шаг 1. Выложить всё на GitHub Pages

1. Создайте **публичный** репозиторий на GitHub (например `grani-miniapp`). Публичный — обязательно, иначе Pages не будет отдавать файлы.
2. Загрузите **всю папку целиком, с сохранением структуры** — `index.html`, `.nojekyll`, `.github/workflows/…`, `scripts/…` и `tabs/utilsbor/…`:
   - Самый надёжный способ — **GitHub Desktop**: File → Add local repository → указать папку → Publish repository.
   - Через сайт GitHub (Add file → Upload files) тоже можно, но нужно перетаскивать именно папки целиком, а не отдельные файлы, иначе вложенность потеряется.
3. **Settings → Pages → Source**: **Deploy from a branch**, branch `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты появится ссылка:
   ```
   https://ВАШ_ЛОГИН.github.io/grani-miniapp/
   ```
5. Откройте её в браузере — должен открыться главный экран. Нажмите «Рассчитать утильсбор» — должен открыться калькулятор и загрузить базу.

⚠️ Ссылка обязательно `https://`, не `http://`.

---

## Шаг 2. Создать бота через BotFather (если ещё нет)

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. `/newbot` → имя бота (например `Брокер ГРАНИ`) → username, оканчивающийся на `bot` (например `grani_broker_bot`).
3. Токен, который пришлёт BotFather, для запуска самого мини-приложения не нужен — сохраните на будущее, если понадобится отдельная логика бота.

Если бот уже есть — используйте его, новый заводить не нужно.

---

## Шаг 3. Подключить мини-приложение к боту

### 3.1. Кнопка меню (рекомендуется)

1. В BotFather: `/mybots` → выберите бота.
2. **Bot Settings → Menu Button → Configure Menu Button**.
3. **URL** — ссылка на GitHub Pages из шага 1, ровно на корень (`.../grani-miniapp/`), не на подпапку `tabs/...`.
4. **Текст кнопки** — например `Открыть приложение`.

Готово — у бота появится кнопка, открывающая главный экран.

### 3.2. (Опционально) Отдельная Web App в общем меню Telegram

1. В BotFather: `/newapp` → выберите бота.
2. Название, описание, иконка 640×360.
3. Web App URL — та же ссылка на корень.

---

## Шаг 4. Проверка

1. Откройте бота, нажмите `/start`, затем кнопку меню.
2. Должен открыться главный экран «Брокер ГРАНИ» с плиткой «Рассчитать утильсбор».
3. Нажмите её — откроется калькулятор, загрузит справочник и таблицу ставок.
4. Введите `Mazda CX-5 2026` — должен найти модификации и посчитать утильсбор.
5. Кнопка ← в шапке калькулятора возвращает на главный экран; ↺ — очищает переписку и начинает заново.
6. Закройте и снова откройте мини-приложение — переписка должна восстановиться (хранится в облаке Telegram, привязана к пользователю).

## Ускорение загрузки справочника (~7 раз быстрее)

Исходный `spravochnik.xlsx` весит ~23 МБ — на мобильном интернете это заметная пауза при первом открытии. Чтобы это ускорить, робот автообновления сразу после скачивания нового `spravochnik.xlsx` с Яндекс.Диска запускает `scripts/convert-spravochnik.js`, который:

1. Разбирает xlsx точно так же, как раньше это делал браузер прямо на телефоне пользователя.
2. Сохраняет результат в компактном сжатом виде — `tabs/utilsbor/spravochnik.json.gz.b64` (~3 МБ вместо 23 МБ, сокращение примерно на 86%).
3. Коммитит оба файла — `spravochnik.xlsx` (как есть, для истории/проверки) и `spravochnik.json.gz.b64` (то, что реально грузит браузер).

Калькулятор при открытии сначала пробует загрузить сжатый файл — это быстрее и не требует разбирать xlsx на телефоне. Если сжатого файла почему-то нет (например, самый первый деплой до первого запуска автообновления, либо `.json.gz.b64` случайно удалили) — он автоматически откатывается на прямое чтение `spravochnik.xlsx`, чуть медленнее, но так же надёжно работает.

**От вас никаких действий не требуется** — оба файла обновляются вместе, автоматически, при каждом срабатывании робота. Пока идёт загрузка (первая или после обновления справочника), в шапке калькулятора появляется надпись «Загрузка базы…», чтобы не выглядело зависшим.

## Автообновление справочника с Яндекс.Диска

В `.github/workflows/update-spravochnik.yml` уже настроен робот, который:
- каждый час сам заходит на Яндекс.Диск по ссылке `https://disk.yandex.ru/d/VeYxsi3IcnmK2w`,
- ищет файл, имя которого начинается с «Справочник технических характеристик» (дата/время в конце имени игнорируется, берётся самый свежий),
- скачивает и кладёт его в `tabs/utilsbor/spravochnik.xlsx`,
- сразу же пересобирает сжатую версию `tabs/utilsbor/spravochnik.json.gz.b64` (см. раздел выше),
- коммитит оба файла в репозиторий — если содержимое действительно изменилось.

**От вас ничего не требуется** — просто держите актуальный файл в этой папке на Яндекс.Диске.

### Проверить, что робот работает
1. Вкладка **Actions** в репозитории → workflow «Обновление справочника с Яндекс.Диска».
2. **Run workflow** — запуск вручную, не дожидаясь часа.
3. Зелёная галочка = обновилось. Красный крестик → откройте лог, там понятная причина (например, не нашёл файл с нужным началом имени — покажет список файлов в папке на Диске).

Дата последнего реального обновления тихо сохраняется в `tabs/utilsbor/spravochnik_last_update.txt` (создаётся автоматически при первом обновлении) — не отображается в интерфейсе, но можно посмотреть в репозитории.

### Если поменяете ссылку/имя файла на Яндекс.Диске
Откройте `.github/workflows/update-spravochnik.yml`, поправьте в начале:
```yaml
YANDEX_PUBLIC_URL: "https://disk.yandex.ru/d/VeYxsi3IcnmK2w"
FILE_NAME_PREFIX: "Справочник технических характеристик"
```

## Обновление данных вручную

| Файл | Как обновляется |
|---|---|
| `tabs/utilsbor/spravochnik.xlsx` | Автоматически, раз в час, с Яндекс.Диска — ничего делать не нужно |
| `tabs/utilsbor/spravochnik.json.gz.b64` | Тоже автоматически, тем же роботом сразу после обновления xlsx |
| `tabs/utilsbor/rates.xlsx` | Вручную: меняется только когда меняется законодательство. GitHub → зайти в `tabs/utilsbor/` → Add file → Upload files → выбрать новый файл с тем же именем `rates.xlsx` — он перезапишет старый |

Код (`index.html` калькулятора) трогать не нужно ни в одном из случаев — он читает файлы по имени при каждом открытии страницы.

## Как добавить новую вкладку в будущем

Ничего в существующих файлах менять не нужно:

1. Создайте новую папку, например `tabs/eptc/`.
2. Положите туда свою самостоятельную страницу `tabs/eptc/index.html` (с собственными `<script>`, стилями, данными — по образцу `tabs/utilsbor/index.html`; в шапке сделайте кнопку «назад» на `../../index.html`).
3. В корневом `index.html` найдите нужную плитку в `.home-grid` и замените:
   ```html
   <button class="home-tile" type="button" data-soon="1">
   ```
   на
   ```html
   <button class="home-tile" type="button" onclick="window.location.href='tabs/eptc/index.html'">
   ```
   (то есть просто убираете `data-soon="1"` и добавляете переход).
4. Загружаете новую папку и обновлённый корневой `index.html` на GitHub — готово, вкладка «Утильсбор» при этом не затронута и продолжает работать как раньше.

## Технические детали

- **Разделение ответственности**: `index.html` в корне отвечает только за визуал/навигацию главного экрана. `tabs/utilsbor/index.html` — полностью самостоятельная страница со своей логикой расчёта, не зависит от главного экрана и не подключается к нему кодом — переход между ними обычная навигация браузера (`window.location.href`), поэтому вкладки можно спокойно редактировать по отдельности, не боясь что-то сломать в другом месте.
- **Telegram WebApp SDK**: подключён в обоих файлах независимо (`tg.ready()`, `tg.expand()`, синхронизация темы). Кнопка `BackButton` Telegram скрыта на главном экране и показана на вкладке — ведёт обратно на `index.html`.
- **CloudStorage**: логика сохранения переписки (сжатие в base64, чанки ≤3500 симв. из-за лимита Telegram в 4096 симв. на ключ, ключи `us1_n`, `us1_c0`, `us1_c1`, …) находится целиком внутри `tabs/utilsbor/index.html`, в отдельном блоке в начале `<script>`, никак не пересекается с логикой расчёта ниже по файлу.
- **Загрузка справочника**: браузер сначала пробует `spravochnik.json.gz.b64` (сжатый, быстрый), при неудаче — откатывается на прямой разбор `spravochnik.xlsx` через SheetJS. Обе ветки приводят к одинаковой внутренней структуре данных, поэтому результат поиска идентичен независимо от того, какой путь сработал.
- **Расчётная логика утильсбора, парсинг СБКТС, фаззи-поиск по базе** — без изменений, как вы прислали.
