# Обязательные правила работы с проектом «Брокер ГРАНИ»

Перед любым изменением кода обязательно полностью прочитать
[`docs/LOCKED_RULES.md`](docs/LOCKED_RULES.md).

## Порядок внесения изменений

1. Сначала определить точный контур задачи: главный экран, мини-приложение,
   поиск по справочнику СЭП, обработка СБКТС, обработка ЭПТС, расчёт
   утильсбора, расчёт пеней, Telegram-бот или архив заявок.
2. Менять только названный пользователем контур. Не проводить попутный
   рефакторинг и не менять соседнюю логику без отдельного согласования.
3. Не удалять поля, шаги диалога, расчётные ветки и элементы результата,
   если пользователь прямо не попросил об их удалении.
4. Правила из `docs/LOCKED_RULES.md` считаются неизменяемыми. Если запрос им
   противоречит, остановиться, показать противоречие и запросить решение
   пользователя. Самостоятельно выбирать новое правило запрещено.
5. Не добавлять в код списки конкретных марок или моделей для решения общей
   задачи. Поиск и ветвление должны работать по данным и одинаковым правилам
   для всех автомобилей.
6. До публикации проверить `git diff`, убедиться в отсутствии посторонних
   изменений, выполнить все существующие тесты и добавить регрессионный тест
   на исправляемую ошибку, когда это возможно.
7. После публикации проверить фактически развёрнутую версию, а не только
   успешный коммит в GitHub.

## Изменение самих правил

`docs/LOCKED_RULES.md` можно менять только после прямого согласования с
пользователем. Любое согласованное изменение правила должно сопровождаться
датой и краткой записью в журнале в конце документа.
